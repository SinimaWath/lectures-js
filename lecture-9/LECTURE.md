# Архитектура навигации

## MPA - Multi Page Application

При переходе загружается новая страница с сервера.

Click Link -> Request -> HTML genaration -> New Sessions (отрыли страницу) -> Rendering -> Show Content

Минусы:

- White Flash.
- Потеря состояния. (Частично)
- Избыточность данных.
- Задержка.

Плюсы

- Просто.
- Нативные технологии.
  - Поддержка
  - СЕО

Когда брать:

- Блоги.
- Новости.
- Документации.
- Лендинги.

## SPA - Single Page Application

Одна HTML-страница, дальше интерфейс и навигация обновляются в браузере без полного reload.

Click Link -> JS перехватываем событие перехода и отменяем его -> Загрузка JSON / Загрузка JS / Загрузка CSS -> Перерисовываем только то что нужно -> Show content.

Минусы:

- Сложно (Роутер, Загрузку данных, Загрузку ресурсов, Кешировать, Собрать vite)
- SEO. Без javascript нельзя проиндексировать.
- Initial load (Первая загрузка) очень долгая.

Плюсы:

- White Flash.
- Потеря состояния. (Частично)
- Избыточность данных.
- Задержка на переходы.

# Архитектура рендеринга (отрисовка)

## SSR (Server Side Rendering)

Используется в MPA

HTML на сервере "формируется".

- Серверный React
- Шаблонизатор Pug

## CSR (Client Side Rendering)

Используется в SPA

HTML собирается на клиенте в браузере.

- Клиентский React

## SSG (Server Side Generation)

Сложный механизм сборки страниц. И отдача с CDN / Кешей.

## ISR (Incremental Server Rendering)

Генерация страницы когда приходит пользователь -> Положили в кеш / cdn.

## Island Arch

## React Server Components (Dynamic Streaming html)

| Подход | Что происходит                                                                                                                                               | Когда подходит                                                                 |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| CSR    | HTML/UI в основном собираются в браузере через JavaScript, что хорошо для интерактивных SPA, но SEO обычно слабее, чем у серверных или статических подходов. | Кабинеты, внутренние панели, приложения с высокой интерактивностью.            |
| SSR    | HTML рендерится на сервере на каждый запрос, поэтому удобно отдавать актуальные данные и SEO-дружественную разметку.                                         | Новости, e-commerce, страницы с персонализацией или часто меняющимися данными. |
| SSG    | Страницы генерируются на build time и потом отдаются из кsша/CDN, что дает быстрый ответ и низкую нагрузку на сервер.                                        | Блоги, маркетинговые страницы, документация.                                   |
| ISR    | Страницы предгенерируются как в SSG, но могут периодически перевыпускаться после деплоя, чтобы данные не устаревали.                                         | Каталоги товаров, контент, который должен быть быстрым, но иногда обновляться. |
