# Архитектура навигации

## MPA - Multi Page Application

0. Юзер кликает на ссылку
1. Браузер делает запрос на сервер
2. Сервер -> Генериует новый HTML
3. Бразуер, очищает память, меняет урлы и ....
4. Браузер рендерит страницу: HTML => DOM, CSS => CSSOM, JS => Render, Layout, Compistion .....
5. Она показывается пользователю

Минусы:

- White Flash
- State Loss
- Избыточность данных.
- Net = Задержка + Обработка ошибок.

Плюсы:

- Простота => Вам даже не нужен JS, вам нужен просто сервер, который отдает HTML.
- Независимость страниц
  - Проще новые страницы делать + проще поддерживать.
  - Разделять между команды
- Проще для CEO
  - Роботам проще скачать HTML.

## SPA - Single Page Application.

0. Клиент: Юзер кликает на ссылку
1. Клиент: делаем запрос за данными
2. Сервер отвечает запросом.
3. Клиент: Формируем HTML
4. Клиент: Отрисовываваем HTML (element.innerHTML = "")
5. Она показывается пользователю

Минусы:

- Сложнее сделать. Нужно много JS
- Тяжелый initial load.
- Хуже SEO.
- Больше точек отказа.

Плюсы:

- Решает проблемы MPA

# Архитектура отрисовки

## CSR - Client Side Rendering

В браузере через JS

## SSR - Server Side Rendering

HTML ренредится на сервере.

---

## \* ISR (Incremental Server Rendering)

Как только открыли страницу => Формируем HTML => Кладем в кеш / cdn

## SSG (Server Side Generation)

Запускаете сборку / отрисовку => Кладете сразу в cdn / кеш / файл.

## Island Arch

Отдельные части страницы рисуете в SSR а отдельные на CSR.

---

## Современные приложение (Notion / Discord / T-Bank)

SPA => CSR + SSR

## Современные сайт (Кинопоиск-документация / learn javascript ru)

MPA => SSR или SSG / ISR
