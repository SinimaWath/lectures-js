# Lecture 10 - Bundler Vite

Учебный пример показывает, как Vite работает не только как dev server, но и как настраиваемый бандлер.

## Запуск

```bash
npm install
npm run dev
```

## Что здесь показано

### 1. Лоадер

- Файл: `src/content/bundler.lesson`
- Настройка: `lessonLoader()` в `vite.config.ts`
- Где видно: карточки на странице создаются из файла с нестандартным расширением `.lesson`
- Зачем нужен: позволяет импортировать собственные форматы файлов и преобразовывать их в JS-модуль прямо во время сборки

### 2. Плагин

- Файл: `vite.config.ts`
- Настройка: `lectureToolsPlugin()`
- Где видно: приложение получает данные из `virtual:lecture-meta`, а в `index.html` добавляется атрибут `data-powered-by`
- Зачем нужен: расширяет Vite собственными хуками, virtual modules и поведением dev server

### 3. HMR

- Файл: `src/content/hmr-message.ts`
- Настройка: `server.hmr` в `vite.config.ts`
- Где видно: измените текст в `hmr-message.ts` во время `npm run dev` — на странице обновится только один блок, без полной перезагрузки
- Зачем нужен: ускоряет обратную связь при разработке, потому что меняется только нужный модуль

### 4. SCSS

- Файлы: `src/style.scss`, `src/styles/tokens.scss`
- Настройка: `css.preprocessorOptions.scss.additionalData`
- Где видно: карточки и бейджи используют переменные и mixin без ручного `@use` в каждом файле
- Зачем нужен: удобно хранить общие токены, темы, mixin и переиспользуемые стили

### 5. SWC

- Файл: `src/examples/swc/decorated-label.ts`
- Настройка: `swcExamplesPlugin()` в `vite.config.ts`
- Где видно: пример с декоратором проходит через SWC и показывает результат в интерфейсе
- Зачем нужен: позволяет точечно использовать другой трансформер, если проекту нужен особый синтаксис или отдельная стратегия компиляции

### 6. Оптимизация чанков

- Файлы: `src/examples/chunks/*`
- Настройка: `manualChunks()` в `vite.config.ts`
- Где видно: по кнопке подгружается отдельный ленивый модуль; после `npm run build` в `dist/assets` появится chunk `feature-lab-*`
- Зачем нужен: редкие и тяжёлые сценарии не попадают в первый пакет и загружаются только по требованию

### 7. Tree shaking

- Файл: `src/examples/tree-shaking/pricing.ts`
- Настройка: `rollupOptions.treeshake`
- Где видно: приложение импортирует только `formatBundlePrice`, а неиспользуемый отладочный код остаётся вне production bundle
- Зачем нужен: уменьшает размер сборки за счёт удаления неиспользуемых экспортов

## Что удобно проверить после сборки

```bash
npm run build
rg "TREE_SHAKING_SENTINEL__THIS_TEXT_SHOULD_NOT_APPEAR_IN_DIST" dist
rg "feature-lab" dist/assets
```

- Первая команда ничего не должна найти: это подтверждение tree shaking для неиспользуемого кода.
- Вторая команда покажет отдельный chunk для ленивой функции.
